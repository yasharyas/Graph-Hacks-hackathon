# Patient Zero: Phase 3 round 6, keyboard and screen-reader QA

Persona: keyboard-only screen-reader user (`keyboard.press` only for navigation and activation), judged against WCAG 2.2 AA: visible focus, logical order, no traps, focus not obscured, sensible live regions, roles/names/states, reduced motion, forced colors, reflow at 400%.

Method: headless Chromium via Playwright (`playwright-skill` install). Production build `localhost:8080` for everything; Vite dev `localhost:5173` re-run for axe (all 26 states), the announcement counts and the skip-link / focus-visibility checks (identical results). Viewports 1440x900, 1280x720, 1024x768, 375x812 and 320x256 as asked, plus 1180x820, 1100x700, 1023x700, 768x1024 and 720x450 (200% zoom) where round 5 had found defects. axe-core (repo copy) injected in every state with all rules plus the wcag2a/2aa/21a/21aa/22aa + best-practice tag set. **The CSP never had to be bypassed**: the axe source is injected with `page.evaluate(source)` (Runtime.evaluate is not subject to the page CSP), and the text-spacing override is applied with a constructed stylesheet, so the whole run, including axe, used the production CSP as shipped. A MutationObserver recorder on `[aria-live]` / `role=status|alert|log` flags regions **inserted already holding text** (`INSERTED-WITH-CONTENT`) and ignores regions that are not rendered. New this round: every focus check hit-tests a 5x5 grid over the part of the focused element that is inside the window (`elementFromPoint`), so "visible" means "inside the window and not covered or clipped", not just "inside the viewport rectangle" (the check I got wrong in round 4). One pass each with `prefers-reduced-motion: reduce` and `forced-colors: active`. No repo file edited, no commits, `.env` not read. Other QA agents shared the servers, so absolute timings are approximate; counts and focus facts are exact. Screenshots: `phase3r6-a11y/` (155 files).

Limits: no real NVDA/JAWS/VoiceOver. "Announced" means "a polite/assertive live region changed text".

## 1. Verdict

**Every blocker from round 5 is fixed and verified with the stricter hit-test. No WCAG 2.2 AA failure found this round. Overall 9.0/10 (round 5: 8.8); accessibility 9 (round 5: 8). Bar met, with a thin margin: eight small nice-to-haves remain and none blocks a 9.**

What got better, in one breath: "Skip to tool calls" now puts the card header fully inside the window at all 7 viewports I tried (round 5: hidden at every one); the 1024 to 1279 band no longer has a page-taller-than-window pane at all (1024x768 is a three-pane screen that fits, so "Show all rows" and "Skip to Ask" land in view); at 200% and 400% zoom the focused Ask input, "Hide plan" and the claim-chip target stay in view after their actions (174 Tab stops at 320x256, 720x450 and 375x812, none hidden or covered); the scenario arrows no longer restart a paused autoplay (clock jumps to the end state, 0 captions); the first scrub at 375 now speaks the one status; a new 4th skip link ("Skip to the Feed, Graph and Table bar") makes the phone panel bar 4 Tabs from the feed (was 34); a claim chip speaks one status (was two); Cypher blocks are wrapped, never overflow, are not tab stops and are `role=group` (no more 21 to 75 region landmarks); the Details tabs' `aria-controls` resolve; Esc dismisses a hover tip; axe is clean in every state on both builds.

What is left, all small: at under 768px the first status of a run ("Starting the triage") is inserted into a freshly mounted live region (the page `main` is re-keyed); the guest re-check can show one `<body>` focus frame (2 of 3 runs); every table tier cell still carries its definition in its accessible name (21 times); "Back to 13:30 UTC" is 30 Tab stops from the slider; plus ARIA / copy nits (section 6).
