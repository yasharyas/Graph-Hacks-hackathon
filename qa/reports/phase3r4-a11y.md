# Patient Zero: Phase 3 round 4, keyboard and screen-reader QA

Persona: keyboard-only screen-reader user (`keyboard.press` only for navigation and activation). Headless Chromium via Playwright, 1440x900 and 375x812 (plus 1024x768, 768x1024, 720x450 = 200% zoom, 320x256 = 400% reflow). Dev server `localhost:5173` for the full walkthrough; production build `localhost:8080` re-run for axe (all 26 states), the triage journey, the skip links and announcement counts. axe-core (repo copy) in every state, run twice (all rules, then the wcag2a/2aa/21a/21aa/22aa + best-practice tag set). A MutationObserver recorder on `[aria-live]` / `role=status|alert|log`; this round it also **flags a live region that is inserted already holding its text** (`INSERTED-WITH-CONTENT`), because most screen readers do not speak those, and I count them separately. One pass each with `prefers-reduced-motion: reduce` and `forced-colors: active`. No repo file edited, no commits, `.env` not read. Other QA agents were using the same servers, so absolute timings are approximate; counts and focus facts are exact. Two screenshots from a slip in my own navigation were deleted from the output folder. Screenshots: `phase3r4-a11y/`.

Limits: headless Chromium, no real NVDA/JAWS/VoiceOver. "Announced" means "a polite/assertive live region changed text"; real speech may coalesce rapid changes. The prod server sends a strict CSP, which blocks axe injection, so the prod axe run used Playwright's `bypassCSP` (only for injecting axe); every other prod check ran without it.

## 1. Verdict

**Round 3's six blockers are all fixed and verified with evidence. Round 4 gate: two real WCAG AA findings remain (1.4.3 contrast in two dimmed states, 1.4.10 reflow of the landing page at 320x256); everything else is clean. Overall 8.8/10 (round 3: 8). Accessibility is 8, not 9, solely because of those two; both fixes are small CSS changes.**

What got better, in one breath: the false "The clock moved to 00:00 UTC" status is gone (0 occurrences across qix, axios, re-run after axios, free text, pasted lockfile, share links); the slider is quiet (**0 announcements per 10 steps** at 150/400/700/1200 ms when stepping inside a run, **1** per 10 when the report-clock strip first appears, down from 22 to 40); Undo keeps focus in both places and announces; "Show all N rows" keeps its toggle in view; a new "Skip to tool calls" link takes 1 Tab + Enter instead of 55 Tabs (23 plain Tabs now); the Ask answer is spoken as words and sits fully above the pinned Ask bar; the slider track and ticks now show in forced colors; Undo no longer expires; the toast can no longer fire on a plain run and, when one does fire (Export), never covers the focused element.

What is left: **two blocking findings** (1: the dimmed narrative while the clock is scrubbed, and the remediated table row, fall under 4.5:1; 2: at 320x256, i.e. 400% zoom of a 1280x1024 window, the landing page scrolls sideways by 33 px and the primary "Run triage at 13:30 UTC" button is cut off; round 3 only measured that viewport after a triage, where it is fine), plus eight small nice-to-haves (autoplay noise when the slider has focus, guest re-check focus drop and duplicate statuses, burst of progress ticks on a fast stream, first-scrub region inserted with content, a few name nits).
